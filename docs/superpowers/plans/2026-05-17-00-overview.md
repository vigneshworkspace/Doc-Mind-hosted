# DocMind Backend Completion — Overview & Plan Index

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement each phase task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Take DocMind from a mock-only UI + half-wired FastAPI scaffold to a fully working full-stack study app — every button hits real backend, every backend endpoint does real work.

**Architecture:** FastAPI + Postgres+pgvector + Redis + ARQ workers + React frontend. LLM/embedding/STT/TTS/vision/parsing are all open-source local-first where possible, with a multi-provider LLM router. Long-running work (parsing, embeddings, generation, TTS) goes through ARQ jobs; chat streams over SSE; voice over FastRTC WebRTC.

**Tech Stack:**
- Backend: Python 3.11, FastAPI, SQLAlchemy 2, Alembic, pgvector, ARQ, sse-starlette, httpx, bcrypt, python-jose
- AI: copied `shared/ai` LLM router (openai/gemini/ollama/groq/nvidia), Docling, faster-whisper, Kokoro-82M (ONNX), Nomic Embed v1.5 (text + vision), FastRTC
- Frontend: React 18 + Vite, lazy screens, `src/api/*.js` real fetches
- Infra: docker-compose (db, redis, backend, worker, fastrtc, frontend)

---

## Stack Decisions (locked 2026-05-17)

| Concern | Pick | Rationale |
|---|---|---|
| Doc parsing | Docling | Layout-aware PDF/DOCX/PPTX, built-in OCR, MD/JSON export |
| Voice-to-voice | FastRTC | WebRTC + swappable STT/TTS/LLM, Python-native |
| STT | faster-whisper | GPU when available, CPU fallback, CTranslate2 backend |
| TTS | Kokoro-82M | 82M params, multi-voice, fast CPU, Apache-2 |
| Vision/OCR | Docling OCR | Already present via Docling, no extra dep |
| Multimodal embed | Nomic Embed v1.5 pair | Vision + text share 768-d space |
| Vector store | pgvector | Reuses existing Postgres |
| LLM router | Copy `shared/ai/` from Lexi project | User-built, supports gemini/openai/ollama/groq/nvidia + key rotation |
| YT ingestion | Copy `youtube_transcript/` from Lexi | youtube-transcript-api + Playwright cookie fallback |
| Job queue | ARQ + Redis | asyncio-native, fits FastAPI |
| Chat stream | SSE (sse-starlette) | one-way, simpler than WS |
| Diagrams | Mermaid | LLM emits mermaid text, frontend renders |
| JWT | Long-lived 7 days | No refresh tokens in v1 |
| OAuth | None v1 | Out of scope |

## Execution model

Recommended: **subagent-driven-development**. Dispatch a fresh subagent per task; main thread reviews between tasks. Each phase produces a green pytest run + a git commit per task.

Each plan file is self-contained: it states which files exist, what to add, exact code, and what to verify. A subagent can be handed a single phase and execute it without re-reading the others, except for phase dependencies declared at the top of each.

## Repo conventions

- Backend lives in `Doc-Mind-hosted/backend/`.
- Frontend lives in `Doc-Mind-hosted/frontend/`.
- All new ARQ workers go in `backend/app/workers/`.
- All new Pydantic schemas go in `backend/app/schemas/schemas.py` (single file already in repo).
- All new routers go in `backend/app/routers/`, registered in `backend/main.py`.
- Tests live in `backend/tests/` (existing pytest+TestClient setup with shared SQLite in-memory).
- Migrations live in `backend/alembic/versions/`.
- File storage volume: `/data/uploads` (mounted via docker-compose), local override `./backend/uploads` for non-docker dev.
